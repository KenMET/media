# Automatic, compact resource browsing

A TV title starts searching all known regular, nonempty seasons automatically, latest first. There is no required season selector, refresh form, episode filter, source filter, sort selector or more-results button. Two existing scoped search requests can run concurrently; completed seasons appear without waiting for the slowest provider. All returned resources are displayed automatically.

Season and partial packs are grouped by descending season (for example S03, S02, S01), followed by single-episode resources, also latest season first. Unknown coverage stays last. Provider order within a season retains the existing quality/availability ranking. A zero-seeder candidate sorts after other candidates within that season. Identical release entries are deduplicated for display; frozen server-owned release IDs and identity checks still authorize downloads.

The title page uses a small poster, compact title and collapsed overview. Each release uses at most two name lines plus one metadata line for site, resolution, size and seeders. The whole row is a keyboard-accessible button at least 60 pixels high; there is no separate row download button. Optional source diagnostics are collapsed below the list. There is no large warning panel above available results.

Select a resource from any season to open its complete name, title, season/episode coverage, source, resolution, size and seeder details. Opening or cancelling this dialog does not request a plan or submit a download. Only Confirm download prepares the existing frozen plan and submits it with its durable idempotency key. There is no fixed latest-season download shortcut. Subscribe opens a season/resolution dialog with explicit Cancel and Confirm subscription actions; only confirmation uses the existing six-hour consent flow. Download originals, seeding, Chinese media names, preferred-version selection and publication safety remain unchanged.

Searches retain the account/server budgets. A rate/concurrency rejection gets one delayed read retry; downloads are never retried by the discovery helper. Failed seasons do not hide other results. Navigating away or refreshing aborts prior discovery and prevents late responses from replacing another page. Special season zero is used only if the title has no regular seasons. Titles without season metadata do not silently invent season one.

`tests/test_release_browser.mjs` covers ordering, coverage groups, concurrency, partial results, cancellation and read throttling. `tests/manual/acceptance_season_workflows.cjs` verifies automatic three-season discovery, compact rows and localized phone/desktop layouts with mocked APIs. `tests/test_season_http.py` verifies that both server roles actually serve the browser module. Run JavaScript tests serially with `node --test --test-concurrency=1`; Python tests use disposable state/media and low CPU priority.

Deploy through `sh setup.sh cloud` for the cloud website. If using the local control server's built-in website, update that role with `sh setup.sh local` at a safe worker checkpoint. Preserve existing environment files, state, ports and service topology. A source commit or browser mock does not prove that the public website has loaded the new image.

Both dialogs support Cancel and Escape before confirmation. Confirmed submissions lock their actions while awaiting a receipt; cancellation does not pretend to undo a download already submitted. A lost, unreadable, malformed or 5xx start receipt retains the original submission key and is reconciled by read-only status lookup. Repeated taps cannot create another submission, and a late season-search response cannot replace the release captured by the dialog. Detail text and subscription fields scroll separately so confirmation/cancellation controls remain reachable on short screens.

One shared movie/TV loading panel shows a spinner and configured Jackett site names above the resource list while any search scope is pending, including when earlier scopes have already returned resources. Site labels show waiting, searching, responded, timed out or failed requests; they describe provider activity, not a season count or a claim that every title query has finished. The indicator disappears after every scope has completed or failed; failed-source diagnostics remain available. Reduced-motion preferences retain the status without animation.

The website opts into newline-delimited JSON on the existing authorized `search_releases` command. Request-local provider events contain only site IDs and statuses; the final message retains the existing JSON command envelope and frozen release records. Authentication, CSRF, download permission and search budgets still apply. Ordinary API/MCP clients keep the JSON response. The gateway disables reverse-proxy buffering for this stream. A bounded progress queue can omit excess intermediate events without dropping the final receipt. Disconnecting stops subsequent provider work at the next progress checkpoint; a current bounded HTTP call may finish first.

TMDB responses are checked for obvious title advertising, including Unicode-obfuscated numeric domains. Chinese responses prefer clean Chinese title fields from the same provider ID in Taiwanese/Hong Kong Chinese metadata before using English or a clean original title. Existing clean Chinese names and original-language fields are preserved. Alternative requests share a 24-second deadline and use bounded per-request timeouts. Clean localized names, dates, scores, ordering and media files are preserved. Unrecoverable entries are omitted; a detail with no usable name fails instead of sending advertising to resource search. Versioned TMDB list/detail cache keys prevent reuse of previously polluted catalog snapshots.
